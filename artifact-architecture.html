Architektura i UI/UX

Master Quest Mobile

Wieloplatformowa aplikacja mobilna do nauki teorii muzyki — family-friendly, freemium, jedna baza kodu obsługująca dwa tryby prezentacji: pełną gamifikację dla dzieci i czysty interfejs dla dorosłych hobbystów.

Założenie robocze: to osobny projekt mobilny (Expo/React Native), niezależny od istniejącej aplikacji webowej master-quest (Next.js) — dzieli z nią koncepcję programową (te same 9 krain), ale ma własny stack i cykl wydawniczy. Realny szkielet kodu towarzyszący temu dokumentowi (typecheck + testy przechodzą czysto) leży w repo master-quest-mobile/.

Grupa docelowa i założenia produktowe

Model biznesowy: freemium — 3 pierwsze krainy zawsze darmowe (hak akwizycyjny), 6 kolejnych za subskrypcją miesięczną lub roczną (z rabatem). Płatność wyłącznie przez In-App Purchase (Apple/Google) — wymóg sklepowy dla treści cyfrowych konsumowanych w aplikacji.

Styl wizualny: flat design, wektorowe ilustracje w duchu Pixar/Duolingo — ciepłe, zaokrąglone kształty, nasycone ale nie krzykliwe kolory. Jeden spójny system wizualny obsługuje dwa tryby prezentacji przez warianty tego samego komponentu, nie przez dwie osobne aplikacje.

Dual-Mode UX: przełączanie profilu

Wybór trybu pojawia się przy pierwszym uruchomieniu (ProfilePickerScreen) i w każdej chwili w Ustawieniach. Zmiana profilu nie resetuje postępu — to wyłącznie warstwa prezentacji plus kilka przełączników zachowania.

Co się różni między trybami

Młody Odkrywca

Duże ilustrowane stworki na mapie, animacje idle, confetti i kryształki za poprawną odpowiedź, lektor czyta polecenia, duże tapnięcia (min. 56×56pt), zaokrąglenia 24px.

Hobbysta / Uczeń

Czyste kafle z ikoną i nazwą, subtelny checkmark zamiast animacji, panel: streak dni, % poprawnych, tryb testowy bez czekania na audio, zaokrąglenia 12px, więcej informacji na ekranie.

Zasada projektowa: to nie są dwa drzewa komponentów. WorldNode.tsx czyta theme.playfulMode i renderuje wariant — jedno źródło prawdy dla logiki odblokowania i nawigacji, zero rozjazdu zachowania między trybami.

03

Mapa krain i progresja

Krainy 1–9 są liniowo zależne — kraina N odblokowuje się dopiero po ukończeniu N−1, niezależnie od statusu subskrypcji. Subskrypcja odblokowuje dostęp do wejścia, nigdy nie pomija kolejności nauki.

Cztery stany węzła na mapie

completed

Ukończona, dostępna do powtórki.

available

Następna do zrobienia, wizualnie wyróżniona.

locked-progression

Zablokowana — ukończ poprzednią krainę.

locked-subscription

Poprzednia ukończona, brak subskrypcji.

lib/progression/resolveNodeState.ts
function resolveNodeState(world, progress, subscription): WorldNodeState {
  if (progress.completedWorldIds.has(world.id)) return "completed";
  const previous = getPreviousWorld(world);
  const previousDone = !previous || progress.completedWorldIds.has(previous.id);
  if (!previousDone) return "locked-progression";
  if (world.isPremium && !subscription.isActive) return "locked-subscription";
  return "available";
}
04

Ekran płatności i paywall

Pojawia się wyłącznie przy próbie wejścia do krainy 4 lub dowolnej kolejnej locked-subscription — nigdy jako interstitial narzucony w trakcie nauki w darmowej strefie.

Bramka rodzicielska

Zanim paywall pokaże cokolwiek związanego z płatnością: prosta bramka matematyczna (dwucyfrowe dodawanie) — standard branżowy wymagany przez App Store/Play Store dla akcji zakupowych kierowanych do dzieci. Trzy próby, potem 30s odstępu. Pojawia się raz na sesję aplikacji.

Zawartość ekranu

  1. Nagłówek korzyści — konkretne punkty ("Wszystkie 9 krain", "Dyktanda ze słuchu"), nie ogólniki marketingowe.
  2. Wybór planu — miesięczny vs roczny (domyślnie zaznaczony, badge "Oszczędzasz X%" liczony z realnych cen sklepowych).
  3. CTA — jeden przycisk z dynamiczną ceną wybranego planu.
  4. Drobny druk — auto-odnawianie, warunki, "Przywróć zakupy".
  5. "Nie teraz" — zawsze widoczne, nigdy zminiaturyzowane.

Źródło prawdy o subskrypcji: RevenueCat SDK, nigdy własny backend jako jedyne źródło. Webhook Apple/Google → backend tylko jako kopia do analityki, walidacja uprawnień zawsze przez SDK sklepu przy starcie aplikacji.
